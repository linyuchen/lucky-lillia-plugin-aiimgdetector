# SynthID 使用说明

SynthID 默认关闭。打开「SynthID 检测」后，登录按钮、三项凭证和检测超时都在这一组设置内。点击「登录 SynthID」会自动获取并填写凭证；也可以直接手动填写同样的三项内容，无需切换模式。两种获取方式都使用你自己的 Google 账号。

## 登录并自动填写凭证

1. 运行 Bot 的电脑需要安装 Chrome 或 Edge，并能打开桌面窗口。
2. 在 Bot 插件页启用「AI 图片检测」和「AI 服务」，批准「AI 图片检测」的插件界面。
3. 打开「AI 图片检测」设置，打开「SynthID 检测」，点击组内的「登录 SynthID」。浏览器会在 **Bot 所在电脑** 上打开；如果从其他设备访问 WebUI，需要在 Bot 所在电脑操作该窗口。
4. 在网站中完成 Google 登录，以及网站要求的首次使用提示。插件在当前已登录页面准备完成后，自动选择一张不包含用户信息的内置测试 PNG，通过该次检测取得上传标识与网页校验凭据，无需自行选择或准备图片。这一步会使用一次网站检测请求，界面显示「已登录，正在获取检测凭证」。
5. 获取完成后保留登录窗口，登录凭据、上传标识和网页校验凭据会自动填入当前表单。点击弹窗底部「保存」，即可对图片回复「/ai吗」检测。检测继续使用该窗口，保存凭证不会关闭它。检测超时只需填写秒数，默认 30 秒。

如果网站拒绝校验或请求失败，设置页会保留「已登录」并显示具体错误，浏览器保留供查看。可以稍后点击「重新获取凭证」重试；插件不会要求你手动选择测试图片，也不会把失败的请求当作可用凭证。

登录及获取凭证过程中都可以取消。「清除浏览器会话」清除本插件保存的登录会话，不会退出你平时浏览器中的 Google 账号，也不会删除表单或插件配置里已填写的凭证。自动填写的凭证需要对应的浏览器会话才能检测；清除后需重新登录并保存新凭证。需要更换账号时，也按此步骤操作。

登录状态和自动获取的凭证保存在当前 Bot 实例的插件数据目录。保存检测设置时保留当前网页会话；修改触发词、重新加载插件或重启 Bot 会关闭窗口，之后再从保存的登录状态启动浏览器。表单三项全空时会自动恢复已有会话中的凭证；已有手工输入或已保存值时，打开设置和状态轮询不会用旧会话覆盖它们。主动点击登录完成后会填写本次取得的新凭证，仍需保存当前表单。

账号失效时可重新登录。只使用 SynthID 时可关闭 OpenAI 水印检测和看图判断，无需配置模型或 OpenAI API Key；仍需启用提供服务依赖的「AI 服务」插件。

浏览器登录需要可交互的桌面。登录按钮打开的是 Bot 所在电脑的窗口，不是访问 WebUI 的电脑。服务器或容器没有桌面时，可按下面的步骤手动获取凭证。

如果登录窗口打开后自动关闭，查看设置页的登录错误。出现连接重置（ECONNRESET）等网络错误时，在 Bot「代理」插件中将测试地址设为 `https://synthid.com/`，确认当前代理能够访问这个网站。Google 首页能打开并不能保证 SynthID 同样可达；登录页加载失败时，插件会清理启动的浏览器窗口。

## 手动获取与填写凭证

此方式不要求 Bot 安装浏览器。在自己的 Chrome 或 Edge 中获取凭证，直接填写「SynthID 检测」中的三项输入框，然后点击弹窗底部「保存」。登录状态显示的是浏览器会话状态，手动填写后不必等待它变成「已登录」；检测会使用配置中完整的三项凭证。

### 1. 登录网站并录制一次检测

在自己的浏览器打开 [synthid.com/image-detection](https://synthid.com/image-detection)，完成 Google 登录和首次使用提示。按 **F12** 打开开发者工具，在 **Network（网络）** 中勾选 **Preserve log（保留日志）**，然后上传一张测试图片，等待检测完成。

下面的上传标识和网页校验凭据必须来自**同一次检测**，并与登录凭据属于同一个账号。不要自行编写上传标识，也不要混用不同账号或不同检测的值。

### 2. 登录凭据（refresh_token）

在开发者工具切到 **Application（应用）→ IndexedDB → firebaseLocalStorageDb → firebaseLocalStorage**，展开当前账号对应的 `firebase:authUser:…` 记录。

在记录的 `value` 中找到 `stsTokenManager`，复制其中 **`refreshToken` 的完整值**，不要带外围引号，填入「登录凭据」。这里需要的是 `refreshToken`，不是 `accessToken`、`idToken` 或 Google 账号密码。

看不到数据库时，确认网站已完成登录，再刷新开发者工具中 IndexedDB 的数据。只复制自己的账号记录，无需在控制台执行脚本。

### 3. 上传标识（push_filename）

回到 **Network（网络）**，找到刚才上传图片的 `content-push` 请求，在 **Headers（标头）→ Request Headers（请求标头）** 中复制 `Push-Filename`。通常形如：

```text
users/账号ID/files/文件ID
```

如果没有找到该请求，可在 Network 中筛选 `TZRKo`，选择 `batchexecute?rpcids=TZRKo` 的 **POST** 请求，打开 **Payload（负载）→ Form Data（表单数据）→ f.req**，找到其中的 `users/…/files/…` 路径并复制。插件也支持带 `/synthid-demo-drop-zone/ttl_1d/` 前缀的完整路径。

这是网站分配的上传标识，**不是电脑上的文件夹路径**。填入「上传标识」时不要包含外围引号、整个请求体或其他字段。

### 4. 网页校验凭据（bg_token）

打开**同一次检测**的 `batchexecute?rpcids=TZRKo` POST 请求，在 **Headers → Request Headers** 中找到：

```text
X-Goog-Ext-525006476-Jspb
```

推荐复制这个请求头的**完整 JSON 数组**，填入「网页校验凭据」。也可以只复制数组的第 6 项（索引为 `5`），即以 `!` 开头的字符串，不带外围引号。不要复制整个 Headers 列表。看不到该项时，展开 Request Headers，或切换「查看源代码」。

### 保存、更新与退出

填完三项后点击插件设置弹窗底部「保存」，再发图检测。手动凭证检测会用 `refreshToken` 获取并刷新登录令牌；上传标识和校验凭据是否可用于后续图片，由网站决定。网页校验被拒绝不代表 Google 登录已失效。手动填写后遇到校验失败或上传标识被拒绝，可改用插件浏览器登录，或在自己的网页重新检测一张图片，并一起更新后两项。提示登录失效时，重新登录或重新获取当前账号的 `refreshToken`。

三项都作为敏感配置处理，保存后配置接口只返回遮罩值。直接将已保存值改为空白会保留原值，需要更新时粘贴新的完整凭证并保存。关闭「SynthID 检测」即可停止使用这项检测。「清除浏览器会话」不删除配置里的凭证，但自动填写的凭证在清除后需要重新登录更新。

凭证可以代表你的登录身份，请勿发送给他人、放进截图或提交到代码仓库。WebUI 遮罩不等于磁盘加密，Bot 的配置文件也需妥善保管。

自动续期后的登录令牌缓存在本插件数据目录的 `synthid-manual/`，重启后继续使用。该缓存同样属于敏感账号数据，不应分享或提交到代码仓库。

## 检测与网络

登录自动填写与手动填写共用三个输入框。保存的三项与当前浏览器会话取得的凭证一致时，插件使用该会话上传原图，由网站为每张图片生成新的网页校验。独立从自己的浏览器获取并手动填写的凭证通过 HTTP 检测，不要求 Bot 安装浏览器。三项全空但已有登录会话时，继续使用已有会话；部分填写会提示补全。更换登录账号后，需要保存新账号自动填写的凭证。

**登录浏览器和检测都自动沿用 Bot「代理」插件的网络设置。** 浏览器通过 `ctx.http.proxy()` 获取有效地址，使用 Chromium 自身的网络栈；手动凭证检测通过 `ctx.http.fetch()` 请求。连不上 Google 时，应在 Bot 的「代理」插件中设置可用的代理，无需另外设置浏览器代理。浏览器支持 HTTP、HTTPS 和无认证的 SOCKS5 代理；带账号密码的 SOCKS5 请改用同一代理服务的 HTTP 入口。旧宿主未提供代理地址接口时保留 HTTP 转发兼容，但建议更新宿主以使用完整的浏览器网络处理。自己浏览器中获取凭证时，使用的是那台电脑自身的网络设置。Google 密码不会返回 WebUI；自动获取的三项凭证只通过已登录的设置页填入表单，不写入插件日志。

手动凭证检测按账号串行上传和检测，每条队列最多保留 4 个等待或正在处理的任务。浏览器检测在每个 Bot 实例中共用会话与检测队列。服务提示额度不足时按提示等待；插件卸载会取消请求并关闭它启动的浏览器。

检测仅支持图片，最大 20 MB。图片会上传到 Google；结果受网站支持的水印、账号权限、图片处理和服务额度影响。未检出水印不能据此确认是人工图片。

## 常见状态

| 状态 | 处理 |
| --- | --- |
| 尚未登录、登录失效 | 点击「登录 SynthID」，或手动填写当前账号的完整凭证 |
| 等待登录 | 在 Bot 所在电脑的登录窗口中完成 Google 登录与首次使用提示 |
| 已登录，正在获取检测凭证 | 等待插件完成内置测试图片的检测；可点击取消 |
| 已登录，凭证获取失败 | Google 登录已识别，但凭证尚未取得；按具体错误提示处理后点击「重新获取凭证」 |
| 浏览器无法启动 | 确认 Chrome 或 Edge 已安装，Bot 有权限启动桌面窗口 |
| 连不上服务 | 检查网络和 Bot 的代理设置 |
| 检测请求被拒绝（代码 7 / HTTP 403） | 服务未允许本次检测，插件保留登录状态；单凭此代码无法确定具体原因。若响应明确提示额度不足，插件会显示等待秒数 |
| 网页校验未通过 | 按具体错误处理；该提示本身不代表登录失效 |
| 额度暂时用完 | 按提示时间等待 |
| 无法识别结果 | 不视为“未检出”，需要检查网站接口是否变化 |

## 实现与开发验证

前端为 `webui/index.js`，通过宿主 SDK 注册配置编辑器，把登录和凭证放在 SynthID 检测开关内部，获取步骤默认折叠；后端 `src/synthid.ts` 管理登录、持久会话、队列和受 WebUI 鉴权保护的接口。`src/synthid-browser.ts` 使用 `playwright-core` 调用本机 Chrome 或 Edge，不在 npm 安装阶段下载浏览器。`synthid.credentials` 是包含 `refreshToken`、`pushFilename`、`bgToken` 的对象，旧的 `false` 值兼容转换为空对象；三项均声明为 `role('secret')`，由宿主配置保存流程处理遮罩。

普通登录状态只返回凭证版本号，不包含凭证本身。设置页通过带版本号的 `POST /api/aiimgdetector/synthid/credentials` 取得本次登录的凭证；接口受 WebUI 鉴权保护并禁止缓存。仅本次主动登录成功、或初次打开的表单三项全空时自动填写一次，后续轮询不会覆盖手工修改，外层其他未保存的字段也会保留。

会话目录为 `ctx.storage.dir()/synthid-session/browser`，只属于本插件，不读取用户平时使用的浏览器资料。插件私有会话数据包含登录数据和自动获取的凭证，不应发布或分享。旧版直接放在 `synthid` 下的三项凭据不自动启用，仅保留隐藏字段的密码遮罩兼容，避免升级后暴露旧值；当前三项统一保存在 `synthid.credentials` 中。

结果协议参考 [sisi0318/synthid 的 PROTOCOL.md](https://github.com/sisi0318/synthid/blob/a4baf87fbe049950b9120a11a239348fd608c55a/PROTOCOL.md)。上游没有实现登录，本插件新增浏览器登录和自动上传流程。上游没有标准 LICENSE，其 README 写明研究用途及商业集成限制；代码实现不代表发布授权已经明确。

自动化测试隔离真实账号和外网，覆盖登录状态、会话保存与退出、取消及卸载、并发与限流、浏览器原图上传、结果解析和检测回退。真实账号的登录与检测仍应通过上述界面完成验证。

开发验证先执行 `npm run build` 和 `npm test`。安装了 Chrome 或 Edge 的机器可另执行 `npm run test:browser`，用真实浏览器和本地模拟服务验证原生代理、请求头、后台任务、重定向、登录弹窗、Cookie、原图上传、当前登录页面自动选图与取消，以及旧宿主的 HTTP 转发兼容；此测试不连接外网或使用真实账号。

Bot 开发模式通过 tsx 加载源码，还需执行 `node ../../LuckyLillia.Bot/node_modules/tsx/dist/cli.mjs test/synthid-browser.mjs --source`。传入浏览器执行的账号读取脚本使用字符串，避免 tsx 注入的 Node 辅助函数在网页中不存在，导致已登录账号被误判为未登录。测试覆盖实时 Firebase 账号优先于过期的页面状态、IndexedDB 回退和匿名账号排除。
